# Synthesis-quality eval harness

A deterministic, **offline** evaluation harness for the on-device synthesis
pipeline. It scores the *already-recorded* model output checked into the other
demos — it never runs a model, opens a socket, reads the clock, or uses an RNG —
so it runs in CI on a box with no GPU and produces a byte-stable report.

It closes gap **G6** ("no retrieval/synthesis quality eval harness") from the
catch-up proposal and turns the **G1** synthesis-quality concern into numbers.

## What it scores

| Scorer | Question it answers | Method |
|--------|--------------------|--------|
| **Term coverage** | Does the recap surface the session's key facts? | Fraction of a *labeled* expected-terms fixture the recap mentions (case-insensitive substring). |
| **Faithfulness / grounding** | Does the recap invent entities? | Recap entities (identifiers, codes, brand names, proper nouns) absent from the session evidence are flagged as likely hallucinations. |
| **In-language** | Is the recap in the session's own language? | A Unicode script detector compares the recap's alphabetic characters by script, tolerating embedded Latin product names (`MySQL`, `SKU-6310`). |

### Inputs (all already in the repo)

- `demos/executive-personas/results/*.json` — per-persona channel recaps + the
  session datasets in `demos/executive-personas/dataset/*.json` (the grounding
  evidence and the labeled `synthesis.expect_terms_any` term sets).
- `demos/multilingual-rollup/results/rollup_results.json` — the per-language
  synthesis matrix and the recorded 1.7B-vs-4B comparison; evidence comes from
  `demos/multilingual-rollup/dataset/multilingual-rollup.json`.

### Fixtures

- `fixtures/expected_terms.json` — labeled expected-terms per persona / language.
- `fixtures/thresholds.json` — the documented regression-gate floor.

## Usage

```bash
# Regenerate the committed report.
python3 demos/synthesis-eval/run_eval.py

# Regression gate — exits non-zero if any score drops below the documented floor.
python3 demos/synthesis-eval/run_eval.py --check

# Debug: print every computed metric as JSON.
python3 demos/synthesis-eval/run_eval.py --dump

# Unit + regression tests (stdlib only).
python3 -m unittest discover -s demos/synthesis-eval -p 'test_*.py'
```

Output: `docs/technical/synthesis-eval.md` (committed; regenerated by the script).

## Public multilingual leaderboard (C4)

`leaderboard.py` builds **on top of** the scorers above: it rolls the same
recorded recaps up **per language** into a public, reproducible board (the C4
deliverable) — coverage / faithfulness / in-language aggregated across the
multilingual matrix and the same-language executive personas, plus a
1.7B-vs-4B model-tier comparison and an honest **pending** list for
README-claimed SEA/GCC languages that have a labeled fixture but no recorded
model output yet.

```bash
# Regenerate the committed board + machine-readable snapshot.
python3 demos/synthesis-eval/leaderboard.py

# Determinism / regression gate — fails if the committed doc or snapshot drifts.
python3 demos/synthesis-eval/leaderboard.py --check

# Print the computed per-language metrics as JSON.
python3 demos/synthesis-eval/leaderboard.py --dump
```

Outputs:
- `docs/technical/multilingual-leaderboard.md` (committed; regenerated).
- `leaderboard_snapshot.json` (committed; the structured record the gate diffs).

To refresh both docs and run every gate in one shot:

```bash
demos/synthesis-eval/refresh.sh          # regenerate, then verify
demos/synthesis-eval/refresh.sh --check  # verify only
```

## Entity-grounding definition

`recap_entities` is deliberately precision-first (it would rather miss a real
entity than flag a common word as a hallucination). A token is an entity when it
is one of:

- an identifier carrying a digit, ≥2 chars, excluding ordinals (`SKU-8842`,
  `FA-2025-0411`, `BR-2505`, `v2.4.1`, `12,4`; **not** `6th`);
- a CamelCase / internal-uppercase brand token (`CartoNord`, `MySQL`, `VNPay`);
- an ALL-CAPS acronym of length 3–6 (`SKU`, `EUR`, `OTA`);
- a capitalised proper noun ≥4 chars that does **not** open a sentence
  (`Adyen`, `Keyence`; a sentence-initial capitalised word is treated as a
  function word, not an entity).

An entity is *grounded* when its case-folded form is a substring of the evidence,
or — for numeric tokens — when its digit run is (so `12,600` is grounded by
`12 600`).

## Relationship to the product crate

The script detector and salient-term tokeniser mirror the Rust implementation in
`crates/synthesis_pipeline/src/eval.rs`, which is exercised by `cargo test`. The
demo harness (over recorded JSON), the CI gate, and the shipped library therefore
agree on what they measure. Keep the two in sync when changing scorer semantics.
